# ADR 0002: Generator plug-ins behind a conditional contract

- Status: proposed (roadmap thread T03, release 2.0)
- Date: 2026-10-27

## Context

relsynth 1.0 has one attribute model, a Bayesian Gaussian copula per table, wired into the engine. The roadmap
adds other model families: CART now, optional neural tabular models (T11), time series (T12), documents (T13), text
(T14) and graphs (T15). They must run inside relsynth's relational skeleton without losing the things users rely
on: exact keys and rules, seed determinism, and datasets that are posterior predictive draws.

## Decision

1. **Only a table's attribute columns are generated by a plug-in.** The engine keeps rows, keys, links, latent
   segments, counts, scaling, rules, uniqueness and the random streams. A plug-in is a *conditional* generator of a
   row's attributes given its context: the latent group, and optionally the parent attributes. This is the
   multi-table pattern of the Synthetic Data Vault (Patki et al. 2016), where parent context conditions a child
   model, and of ClavaDDPM (Pang et al. 2024), with relsynth's latent segments as the context.
2. **The contract** (`relsynth.generators.contract`, version 1.0) has these methods:
   - `fit(data, context, privacy_budget)` and `sample(n, conditioning, rng)`;
   - optionally `posterior_draw(rng, mode)`, `posterior_draws(m, rng)`, `log_prob`, `uncertainty()`,
     `privacy_cost()`, `fitted_groups()`, and `serialize()` / `load()` with a model version;
   - declared `Capabilities`: modalities, column kinds, conditioning, DP support, GPU need, pushdown, posterior,
     log_prob and IR versions.
3. **Discovery** is the standard `relsynth.generators` entry-point group, so a third-party package needs no change
   to relsynth. Built-in names cannot be shadowed. Duplicate names and broken plug-ins are reported, never imported
   silently.
4. **Choice** is per table in the spec (`tables.<t>.generator`: a name or `{name, version, options}`), with a spec
   default `synthesis.generator`. The default is `copula`. `relsynth check` refuses a choice that cannot model the
   table.
5. **The copula is the first plug-in.** Its code moved verbatim behind the contract. It draws the same random
   numbers in the same order, so the output is byte-identical to 1.0.
6. **Compute** devices are a preset file (`compute.yaml`: cpu, gpu-auto, gpu-single, gpu-multi) plus expert
   overrides. A generator's declared GPU need is resolved against them. CPU is the default, and every fallback is
   explicit.

## Alternatives rejected

- **Plug-ins that generate whole tables, keys included** (as SDV's single-table synthesizers do). Rejected because
  every plug-in would have to re-implement key generation, rules and scaling, and relsynth's integrity guarantees
  (Props. 700, 701) would become per-plug-in promises.
- **Plug-ins that see the whole database.** Rejected because they bypass the relational model and its pushdown,
  and the cost and privacy accounting of a run would no longer be per table. T15 (graphs) may need a node-level
  variant of the same contract, which is why `Capabilities.modalities` exists.
- **A class path in the spec** (`generator: mypkg.mod:Cls`). Rejected because it imports arbitrary code named in a
  data file, and it cannot be listed, checked or pinned the way an installed, named entry point can.
- **A framework-specific device API (torch).** Rejected because relsynth stays free of deep-learning dependencies.
  Plug-ins receive a neutral plan (device, ids, precision, batch size, memory, threads) and map it to their
  framework.
- **JSON-only model files.** Not possible for arbitrary plug-ins. Pickle with a header and hash is used instead,
  loaded only with `trusted=True`.

## Consequences

- T07 (DP) plugs into `privacy_budget`, `privacy_cost()` and `Capabilities.dp`.
- T11 adds neural plug-ins against `gpu` and `compute.yaml`. Model selection across plug-ins can use
  `relsynth generators list` and the per-table scorecards.
- T12–T15 extend `modalities` and the conditioning context. The contract version moves to 2.0 if a required
  method changes.
- The exported standalone model (`export-model`) covers copula tables only. Tables with another generator are
  listed in its scope, and their models are saved with `serialize()`.
