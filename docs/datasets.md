# Dataset register

relsynth is open source, so a dataset's terms decide three things: whether it may be used at all, whether its rows (or synthetic data and models fitted to it) may be committed to this repository or published as an example, and where it may be processed. Use a dataset only as its row allows. Add a row, through a pull request reviewed by a code owner, before using a new dataset.

**Columns.**
- *Commercial use*: the terms allow use by a company in a commercial product. Non-commercial data may only be used for local benchmarks whose aggregate results are reported.
- *Commit*: rows, synthetic data or fitted models may be stored in the repository or in published examples. "No" means fetch at run time into the ignored cache and publish aggregate numbers only.
- *Environments*: `local` (a contributor's machine), `CI` (GitHub-hosted runners), `cloud` (any public cloud service, including LLM APIs). Restricted data never goes to `cloud`.
- *Owner*: the roadmap thread that uses it and keeps its row current.
- *Checked*: the date the terms were last read at the link. Rows marked *plan* were carried over from the implementation plan and must be re-read by their owner before first use.

## Rules

1. A dataset that is not in this register may not be used.
2. Restricted data (status *Restricted*) is processed only in the environment named, never in CI or with an online service, and never leaves it, not even as synthetic data. Aggregate results may be reported if the terms allow.
3. Non-commercial data (*Commercial use: No*) is used for local benchmarks only. Publish aggregate results, never rows, synthetic rows or fitted models.
4. The benchmark harness downloads public datasets into an ignored cache and checks their SHA-256 against the value pinned in the harness; it never commits them.
5. When terms change, the owner updates the row and the *Checked* date in the same pull request as any code that depends on it.
