\section{Generator selection}\label{sec:v73selection}
% numbered from 1845; the shared counter is restored at the end
\newcounter{savedpropselect}\setcounter{savedpropselect}{\value{proposition}}
Each table's attribute columns are modelled by a generator plug-in (Section on generator plug-ins). By default the spec names it (\texttt{synthesis.generator}, a table's own \texttt{generator}). \texttt{synthesis.generator\_selection} lets the user ask the engine to choose instead: \texttt{auto} applies documented rules to each table's traits, \texttt{trial} fits, samples and scores every installed candidate on the real data (code \texttt{relsynth/generators/selection.py}). The default stays \texttt{off}. This section states what trial guarantees. It is tested in \texttt{tests/unit/test\_generator\_selection.py}.

\setcounter{proposition}{1844}
\begin{proposition}[Trial selection is privacy first and paired with the release]\label{prop:trialselect}
Let $G$ be the candidates whose trial completed, $T_g$ the selectable tables candidate $g$ can model ($T_g\neq\emptyset$ for $g\in G$), $c_g$ the configuration that puts $g$ on $T_g$ and keeps the spec's generator on every other selectable table, $s_0$ the spec's seed and $m$ the number of trial seeds. For $g\in G$ and $j<m$ let $R_{g,j}$ be the scorecard, privacy items included, of one dataset drawn with configuration $c_g$ and seed $s_0+j$, $p_g=\max_j$ (failed privacy items of $R_{g,j}$: distance to closest record, exact matches, rare-text copies) and $q_g=\frac1m\sum_j$ (share of passed items of $R_{g,j}$). Trial returns $g^\ast=\arg\min_g\,(p_g,\,-q_g,\,[g\neq g_{\rm spec}],\,\mathrm{rank}(g))$ in lexicographic order. and the release uses $c_{g^\ast}$. Then (a) no completed configuration $c_g$ with fewer failed privacy items than $c_{g^\ast}$ exists, and among those with as few, none has a higher mean share; (b) the comparison is paired: every candidate is fitted on the same rows and drawn on the same seeds, so a difference of $q$ is not a difference of random streams of the engine outside the generator; (c) the release is drawn with seed $s_0$ and $c_{g^\ast}$ on the same rows, so its draw is that of $R_{g^\ast,0}$ when the engine is deterministic given its seed, and its scorecard equals $R_{g^\ast,0}$ when the release is evaluated with the privacy items too (the privacy items count in the scorecard; \texttt{test\_trial\_end\_to\_end\_is\_paired\_with\_the\_release} tests this equality); (d) when $g_{\rm spec}\in G$ can model every selectable table and no candidate is strictly better in $(p,-q)$, the release is the one of mode \texttt{off}; (e) tables that name a generator, copied tables and views are not changed.
\end{proposition}
\begin{proof}
(a) is the definition of the lexicographic minimum over the finite set $\{c_g: g\in G\}$; a candidate covering only part of the tables is compared through its configuration $c_g$, which is what would be released. (b) Every candidate receives the same loaded tables and statistics and the seeds $s_0,\dots,s_0+m-1$; the generator is the only part of the spec that differs. (c) The pipeline applies $c_{g^\ast}$ to the spec and fits it on the same rows with seed $s_0$, which is the configuration of $R_{g^\ast,0}$; with a deterministic engine the draw is the same, and a scorecard is a function of the draw, the real rows and the evaluation settings, so it is the same when the release is evaluated with the privacy items, as the trial always is. (d) The third key prefers $g_{\rm spec}$ among the minimisers of $(p,-q)$, and with $g^\ast=g_{\rm spec}$ covering every table, $c_{g^\ast}$ is the spec of mode \texttt{off}. (e) \texttt{selectable} leaves those tables out and \texttt{with\_choice} writes only the others.
\end{proof}
\noindent Trial reads the real data to choose, so its choice is not covered by a differential privacy budget: the spec check refuses it in DP mode, where the generator is named. Ranking by privacy first follows the project's rule that defaults and automatic choices favour privacy; a user who prefers fidelity names the generator.
